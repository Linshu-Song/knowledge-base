訓練工程

強健的模型訓練不僅涉及前向與反向傳播。建構可擴展且具備彈性的訓練管線需要管理狀態、硬體、監控以及匯出模型以供部署。

Lightning Integration

諸如 PyTorch Lightning 之類的框架會自動處理本文中討論的大部分工程樣板程式碼，包括裝置管理、精度控制、訓練迴圈和檢查點。理解這些底層概念對於除錯和擴展這些高階框架至關重要。

訓練迴圈工程​

強健的訓練迴圈負責處理資料迭代、最佳化步驟和評估。

標準範本​

結構良好的訓練迴圈應將前向傳播、損失計算、反向傳播和參數更新分離開來。確保正確呼叫 model.train() 和 model.eval()。

for epoch in range(num_epochs):
    model.train()
    for batch_idx, (data, targets) in enumerate(train_loader):
        data, targets = data.to(device), targets.to(device)
        
        optimizer.zero_grad()
        outputs = model(data)
        loss = criterion(outputs, targets)
        loss.backward()
        optimizer.step()

進階最佳化技術​

  • 梯度累積：透過在呼叫 optimizer.step() 之前累積多個步驟的梯度來模擬更大的批次大小。在嚴格的記憶體限制下非常有用。
  • 梯度裁剪：使用 torch.nn.utils.clip_grad_norm_ 將梯度裁剪到最大範數，防止梯度爆炸。
  • 早停：當驗證指標在預定義的輪數（耐心值）內停止改善時停止訓練，防止過度擬合。

指標計算與日誌記錄​

在訓練和驗證期間追蹤效能指標（準確率、精確率、召回率）和損失。使用指數平滑或簡單的逐輪次累積來維護滑動平均值。

訓練狀態管理​

正確的狀態管理確保訓練可以可靠地暫停、恢復和評估。

檢查點策略​

僅儲存模型權重（model.state_dict()）不足以恢復訓練。完整的檢查點必須包含：

  • 模型權重（model.state_dict()）
  • 最佳化器狀態（optimizer.state_dict()）
  • 排程器狀態（scheduler.state_dict()）
  • 當前輪次和全域步數
  • 最佳驗證指標
checkpoint = {
    'epoch': epoch,
    'model_state': model.state_dict(),
    'optimizer_state': optimizer.state_dict(),
    'loss': loss_value
}
torch.save(checkpoint, 'checkpoint.pth')

恢復機制​

要恢復訓練，載入檢查點並恢復所有組件的狀態。如果需要完全的可重複性，確保同時管理隨機種子。

最佳模型邏輯​

在每個輪次結束時追蹤驗證指標。如果當前指標超過歷史最佳值，則單獨儲存 best_model.pth，以確保無論後續是否發生過度擬合或早停，都能保留最佳權重。

裝置與分散式執行​

高效管理硬體可加速訓練過程。

裝置最佳實務​

避免硬編碼 'cuda' 或 'cpu'。動態分配裝置，並在可能的情況下使用非阻塞資料傳輸。

device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = model.to(device)
# Use non_blocking=True if pin_memory=True in DataLoader
data = data.to(device, non_blocking=True)

混合精度訓練​

torch.cuda.amp 啟用了自動混合精度（AMP），利用 float16 實現更快的計算和更低的記憶體使用，同時在必要時使用 float32 保持模型準確性。使用 GradScaler 防止梯度更新期間的下溢。

除錯與監控​

了解模型的內部狀態對於診斷訓練故障至關重要。

鉤子機制​

PyTorch 提供鉤子（Hooks）來檢查或修改中間張量，而無需改變模型的程式碼結構。

  • 前向鉤子：用於提取中間特徵圖。
  • 反向鉤子：允許檢查流經特定層的梯度。

整合日誌平台​

整合 TensorBoard 或 Weights & Biases (W&B) 等工具，視覺化隨時間變化的損失曲線、學習率和硬體使用率。這些平台提供歷史上下文和實驗追蹤功能。

常見訓練陷阱​

  • 梯度爆炸/消失：監控梯度範數。使用梯度裁剪或調整初始化策略。
  • NaN 檢測：使用 torch.autograd.set_detect_anomaly(True) 識別產生 NaN 值的操作，通常由除以零、不穩定的對數或過高的學習率引起。

模型匯出與部署準備​

將研究成果轉化為生產就緒模型需要標準化。

TorchScript 匯出​

使用 torch.jit.trace（用於靜態控制流）或 torch.jit.script（用於動態控制流）將 PyTorch 模型轉換為獨立於 Python 執行階段的序列化表示。

ONNX 匯出​

開放神經網路交換（ONNX）格式提供了跨各種推理引擎（如 TensorRT、ONNX Runtime）的互操作性。使用 torch.onnx.export 匯出模型。

量化基礎​

透過將權重和啟動從 float32 轉換為 int8，減小模型大小並提高推理速度。PyTorch 支援訓練後量化（PTQ）和量化感知訓練（QAT）。
