混合精度訓練

預設情況下，PyTorch 使用 32 位元浮點數（float32 或 FP32）執行所有張量操作。然而，現代 GPU 包含針對較低精度格式（如 16 位元浮點數 float16 或 FP16 以及 bfloat16 或 BF16）優化的專用硬體（如 Tensor Cores）。

自動混合精度 (AMP) 智能地在較低精度下運行某些操作以節省記憶體並提高速度，同時將需要較高動態範圍的操作保持在 float32。

較低精度的優勢​

  1. 更快的運算：Tensor Cores 處理 16 位元數學運算的速度比 32 位元數學運算快幾個數量級。
  2. 減少記憶體：梯度、激活值和權重佔用更少的 VRAM，從而允許更大的批次大小或更大的模型。
  3. 記憶體頻寬：移動 16 位元數據所需的時間是 32 位元數據的一半，從而緩解了記憶體頻寬瓶頸。

FP16 (Float16)​

FP16 使用 1 個符號位、5 個指數位和 10 個尾數位來表示數字。由於它的指數位少於 FP32，因此其動態範圍較窄，這有時會導致梯度下溢（梯度變為零）。AMP 在底層使用梯度縮放器 (Gradient Scaler) 來防止這種情況。

import torch

scaler = torch.amp.GradScaler('cuda')

for inputs, targets in dataloader:
    optimizer.zero_grad()
    
    # 將操作轉換為混合精度
    with torch.amp.autocast('cuda', dtype=torch.float16):
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        
    # 縮放損失並調用 backward 以創建縮放後的梯度
    scaler.scale(loss).backward()
    
    # 取消縮放梯度並更新權重
    scaler.step(optimizer)
    scaler.update()

BF16 (BFloat16)​

BF16 為指數分配了 8 位（與 FP32 相同），為尾數分配了 7 位。這意味著它具有與 FP32 完全相同的動態範圍，從而消除了梯度下溢問題。然而，它犧牲了小數精度。

BF16 在訓練大型語言模型 (LLM) 和其他不穩定的架構時備受青睞，因為它不需要梯度縮放器。

硬體要求

BF16 需要 Ampere 架構的 GPU（例如 RTX 30 系列、A100）或更新版本。如果您使用的是較舊的 GPU（如 V100 或 RTX 20 系列），則必須堅持使用標準的 FP16。

import torch

for inputs, targets in dataloader:
    optimizer.zero_grad()
    
    # BF16 不需要 GradScaler
    with torch.amp.autocast('cuda', dtype=torch.bfloat16):
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        
    loss.backward()
    optimizer.step()

TensorFloat-32 (TF32)​

TF32 是在 Ampere GPU 中引入的一種特殊格式。它使用 8 位作為指數（如 BF16/FP32），並使用 10 位作為尾數（如 FP16）。

與 FP16/BF16 不同，TF32 不是您將張量轉換成的數據類型。相反，它是 Tensor Cores 的一種內部執行模式。當您將兩個 FP32 矩陣相乘時，GPU 可以在內部使用 TF32 執行數學運算，從而提供巨大的速度提升，而幾乎無需更改代碼。

啟用 TF32

PyTorch 預設情況下會禁用矩陣乘法的 TF32，以確保完美的重現性。要在 Ampere 及以上版本的 GPU 上啟用它以獲得免費的速度提升，請在腳本開始時全局運行此命令。

import torch

# 必須在初始化之前全局運行
torch.set_float32_matmul_precision('high')
