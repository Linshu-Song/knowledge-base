# 学习率调度

选择合适的优化器固然重要，但在训练过程中动态调整学习率（Learning Rate, LR）通常是模型能否收敛到全局最优解的关键。`torch.optim.lr_scheduler` 模块提供了多种策略，根据当前的训练轮次（Epoch）或特定的性能指标来自动更新学习率。

## 工作原理

调度器通过封装一个现有的优化器（Optimizer）来工作。它会随着时间的推移，动态修改优化器内部 `param_groups` 中的 `lr` 属性。

```python
import torch.optim as optim

# 1. 初始化优化器
optimizer = optim.AdamW(model.parameters(), lr=0.1)

# 2. 初始化调度器：例如每隔 30 个 Epoch 将学习率缩小为原来的 0.1
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 训练循环
for epoch in range(100):
    train(...)  # 模型训练
    val(...)    # 模型验证
    
    # 3. 关键：在每个 Epoch 结束时更新学习率
    scheduler.step()
```

:::warning[注意事项]
在 PyTorch 1.1.0 之后的版本中，**`scheduler.step()` 必须在 `optimizer.step()` 之后调用**。如果在其之前调用，会导致训练的第一个 Epoch 跳过初始学习率，直接从第二次调整后的学习率开始。
:::

## 核心调度策略

PyTorch 内置了丰富的调度机制，适应不同的训练场景。

### 等间隔衰减：`StepLR` & `MultiStepLR`

这是最基础的策略。`StepLR` 按固定的周期（`step_size`）进行缩放；而 `MultiStepLR` 则允许你在指定的“里程碑”（`milestones`）处进行缩放。

```python
# 每 30 个 Epoch，LR = LR * 0.1
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 在第 30、80 和 120 个 Epoch 处分别进行衰减
scheduler = optim.lr_scheduler.MultiStepLR(optimizer, milestones=[30, 80, 120], gamma=0.1)
```

### 性能触发衰减：`ReduceLROnPlateau`

当监测的指标（如验证集损失）停止改善时，该调度器会自动降低学习率。这非常有助于模型跳出“鞍点”或在平台期进一步细化权重。

```python
scheduler = optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode='min', factor=0.1, patience=10)

# 循环内部：需要手动传入当前的监控指标
for epoch in range(100):
    val_loss = val(...)
    scheduler.step(val_loss) # 调度器根据 val_loss 的表现决定是否调整
```

### 余弦退火：`CosineAnnealingLR`

按照余弦波形的轨迹动态调整学习率。这种方法非常流行，因为它在前期保持较高的学习率以快速搜索，中后期平滑下降，最后以极小的步长收敛，通常能获得更好的泛化性能。

```python
# T_max 通常设置为总训练步数或总 Epoch 数
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=100, eta_min=1e-6)
```

### 单周期策略：`OneCycleLR`

单周期策略（One Cycle Policy）是近年来极受推崇的技术。它将学习率从一个较低的值逐渐攀升到一个极高峰值（暖机阶段），然后再平滑下降到一个远低于初值的水平。这种“大幅度震荡”有助于跳过局部最优，常能实现所谓的“超收敛（Super-convergence）”。

```python
# 需要知道每轮的步数（DataLoader 的长度）
scheduler = optim.lr_scheduler.OneCycleLR(
    optimizer, 
    max_lr=1e-2, 
    steps_per_epoch=len(train_loader), 
    epochs=100
)

# 注意：OneCycleLR 通常是按“步 (Batch)”更新，而不是按“轮 (Epoch)”
for epoch in range(100):
    for batch in train_loader:
        train(...)
        scheduler.step() # 每个 Batch 更新一次
```

## 调度器对比与选型

| 调度器 | 最佳应用场景 | 优缺点对比 |
| :--- | :--- | :--- |
| **StepLR / MultiStepLR** | 传统经典架构 (如 ResNet) | 逻辑清晰直观 / 硬性阶梯式下降可能导致训练曲线抖动。 |
| **ReduceLROnPlateau** | 不确定具体需要多少 Epoch 才能收敛时 | 动态自适应，随坏随调 / 容易受到评估指标波动的干扰。 |
| **CosineAnnealingLR** | 现代网络训练的标准配置 | 轨迹平滑，收敛稳健 / 需提前明确训练总时长 (`T_max`)。 |
| **OneCycleLR** | 追求极速收敛，针对复杂任务 (NLP/CV) | 能极大缩短训练时间 / 对 `max_lr` 的选取较为敏感。 |
