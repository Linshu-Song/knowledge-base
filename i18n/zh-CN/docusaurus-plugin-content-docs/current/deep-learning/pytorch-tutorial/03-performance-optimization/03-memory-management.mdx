# 内存优化

训练大型模型经常会触及 GPU VRAM 的物理极限。当遇到内存不足 (OOM) 错误时，您无法立即购买更大的 GPU。相反，您可以利用几种内存优化技术，用计算时间换取 VRAM 空间。

## 梯度累加 (Gradient Accumulation)

当您为了避免 OOM 错误而减小批次大小时，梯度会变得更加嘈杂，这可能会影响收敛。**梯度累加**允许您通过在多次较小的正向/反向传播中累加梯度，然后再实际更新权重，从而模拟大的批次大小。

例如，通过运行 4 个大小为 16 的批次，累加梯度，然后执行优化器步骤，可以模拟大小为 64 的批次。这使内存使用量保持在批次大小为 16 的水平，同时提供批次大小为 64 的稳定性。

在原生 PyTorch 中，这需要仔细放置 `zero_grad()` 和 `step()` 调用：

```python
# 步进前累加的微批次数量
accumulation_steps = 4

optimizer.zero_grad()

for i, (inputs, targets) in enumerate(dataloader):
    outputs = model(inputs)
    
    # 缩放损失以解决累加问题
    loss = criterion(outputs, targets) / accumulation_steps
    loss.backward()  # 梯度在此处累加
    
    # 仅每 `accumulation_steps` 次迭代执行一次优化步骤
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()  # 重置梯度以进行下一个累加周期
```

## 梯度检查点 (Gradient Checkpointing)

在正向传播期间，PyTorch 会将中间激活保存在内存中，因为在反向传播（反向传播）期间计算梯度需要它们。对于非常深的模型，存储这些激活会消耗绝大部分 VRAM。

**梯度检查点**（或激活检查点）丢弃这些中间激活以节省内存。在反向传播期间，PyTorch 会即时重新计算它们。这显著减少了 VRAM 使用量，代价是训练时间大约延长 20-30%。

:::info[用计算换内存]
检查点是终极的“计算换内存”权衡。在训练基础模型或处理超高分辨率图像时，这是必不可少的。
:::

要实现这一点，在 `forward` 传递期间使用 `torch.utils.checkpoint.checkpoint` 包装您的子模块。

```python
import torch.nn as nn
from torch.utils.checkpoint import checkpoint

class DeepModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer1 = nn.Sequential(...)
        self.layer2 = nn.Sequential(...)

    def forward(self, x):
        # 正常的正向传播会消耗大量内存
        # x = self.layer1(x)
        
        # 检查点的正向传播节省内存，在反向传播中重新计算
        x = checkpoint(self.layer1, x, use_reentrant=False)
        x = checkpoint(self.layer2, x, use_reentrant=False)
        return x
```

## 梯度裁剪 (Gradient Clipping)

虽然梯度裁剪主要是一种防止梯度爆炸（数值不稳定性）的技术，但它也可以防止 `NaN` 值传播并损坏您的优化器状态。在使用动态范围有限的混合精度格式时，这尤其有用。

```python
import torch

loss.backward()

# 在采取步骤之前，将梯度的范数裁剪为 1.0
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

optimizer.step()
```
