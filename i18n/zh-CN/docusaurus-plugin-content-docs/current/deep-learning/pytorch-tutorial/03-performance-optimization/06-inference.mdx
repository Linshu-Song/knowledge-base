# 推理优化

训练侧重于吞吐量（每秒处理的样本数）和内存效率（梯度）。推理则优先考虑**延迟**（单次预测所需的时间）和**吞吐量**。

因为我们在推理期间不需要计算梯度或更新权重，所以我们可以应用在训练期间无效的几种优化。

## 推理上下文

在运行 PyTorch 模型进行推理时，有两个必须执行的步骤：

1. **评估模式 (Evaluation Mode)**：将 Dropout 和 BatchNorm 等层切换到评估模式。Dropout 被禁用，BatchNorm 使用其学习到的运行统计信息而不是批次统计信息。
2. **禁用梯度**：禁用梯度跟踪可防止 PyTorch 存储中间激活，从而大量节省内存和计算时间。

```python
import torch

# 禁用 Dropout，触发 BatchNorm 的评估路径
model.eval()

# 完全绕过梯度跟踪和中间激活存储
with torch.inference_mode():
    predictions = model(input_batch)
```

## 图优化 (`torch.compile`)

虽然 `torch.compile` 可以加速训练，但它在推理中最耀眼。通过融合操作（例如，卷积 + ReLU），内存带宽使用率显著下降。

对于生产推理，通常使用 `max-autotune` 模式来发现适合您的特定 GPU 架构的最快内核。

```python
import torch

# 将算子融合到统一的执行内核中
fast_model = torch.compile(model, mode="max-autotune")

with torch.inference_mode():
    output = fast_model(input_batch)
```

## 导出到生产环境

在生产环境（例如，在 FastAPI 或 Flask 等 Python 服务器内）中运行原始 PyTorch 模型通常不是最佳选择，这是因为 Python 的全局解释器锁 (GIL) 和开销。相反，模型通常被导出到更快的运行时。

### ONNX

**开放神经网络交换 (Open Neural Network Exchange, ONNX)** 是一种被广泛支持的格式。您可以将 PyTorch 模型导出到 ONNX，然后可以使用 ONNX Runtime (C++) 或 TensorRT (NVIDIA) 运行该模型。

### TensorRT

NVIDIA 的 **TensorRT** 是在 NVIDIA GPU 上部署模型的黄金标准。它执行激进的层融合、精度校准（例如 INT8 量化）以及针对您的特定 GPU 模型的内核自动调整。PyTorch 模型可以通过 ONNX 转换为 TensorRT，或者直接使用 `Torch-TensorRT` 进行转换。

:::note[更多详情]
有关使用 ONNX 或 TensorRT 转换和部署的详细指南，请参阅“深度学习基础”部分。
:::

## 量化 (Quantization)

虽然混合精度 (FP16/BF16) 在训练中很常见，但推理通常可以容忍 **INT8** 精度。

量化将浮点权重的连续空间映射到 8 位整数中。这使模型大小减少了 4 倍，内存带宽减少了 4 倍，从而在配备了整数 Tensor Cores 的现代 GPU 上提供了巨大的速度提升。

*   **PTQ（训练后量化，Post-Training Quantization）**：最简单的方法。使用小型校准数据集查找激活的最小/最大边界，将训练好的 FP32 模型转换为 INT8。
*   **QAT（量化感知训练，Quantization-Aware Training）**：如果 PTQ 严重损害了模型的准确性，QAT 会在训练期间模拟量化误差，从而允许模型适应并保持准确性。
