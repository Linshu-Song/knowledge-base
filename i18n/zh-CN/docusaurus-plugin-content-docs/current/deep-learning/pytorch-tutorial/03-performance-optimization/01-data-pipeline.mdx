# 数据流水线优化

在训练深度学习模型时，GPU 通常比 CPU 快得多。如果 CPU 无法足够快地加载和预处理数据，GPU 将处于空闲状态等待数据。这被称为 **CPU 瓶颈**或 **I/O 瓶颈**。

优化数据流水线主要涉及正确配置标准的 PyTorch `DataLoader`。

## 工作进程数 (Number of Workers)

`DataLoader` 中的 `num_workers` 参数决定了用于数据加载的子进程数。

:::tip[最佳 num_workers]
一个常见的经验法则是将 `num_workers` 设置为可用的 CPU 核心数，或者 `4 * num_gpus`。然而，设置得太高会导致过多的开销和内存消耗。务必进行基准测试以找到最佳平衡点。
:::

## 锁页内存 (Pinned Memory)

在 GPU 上训练时，数据必须从 CPU RAM 传输到 GPU VRAM。默认情况下，这种传输是可分页的，这意味着操作系统可以移动它。锁定内存将数据锁定在特定的 RAM 位置，从而允许更快地、异步地将数据传输到 GPU。

:::note[何时使用 pin_memory]
在 GPU 上进行训练时，请始终设置 `pin_memory=True`。如果仅在 CPU 上训练，请将其保留为 `False`。
:::

## 持久化工作进程 (Persistent Workers)

默认情况下，PyTorch 在一个 epoch 结束时销毁工作进程，并在下一个 epoch 开始时重新创建它们。这种卸载和启动过程需要时间。

:::info[持久化工作进程]
设置 `persistent_workers=True` 可以在 epoch 之间保持工作进程存活。这消除了每个 epoch 开始时的初始化开销，这对于小型数据集或快速 epoch 尤为明显。
:::

## DataLoader 配置示例

在初始化 `DataLoader` 时，可以直接应用这些优化：

```python
from torch.utils.data import DataLoader

train_loader = DataLoader(
    dataset=train_dataset,
    batch_size=32,
    num_workers=8,               # 1. 并行工作进程
    pin_memory=True,             # 2. 快速 CPU 到 GPU 传输
    persistent_workers=True,     # 3. 避免 epoch 重启开销
    prefetch_factor=2            # 4. 提前缓冲批次
)
```
