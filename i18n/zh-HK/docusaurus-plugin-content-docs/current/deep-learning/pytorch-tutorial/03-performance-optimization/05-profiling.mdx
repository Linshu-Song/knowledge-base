# 性能分析與瓶頸

在盲目應用性能優化之前，您必須首先確定瓶頸所在。在深度學習中，瓶頸通常分為三類：

1. **受限於 CPU（數據加載 / 預處理）**：GPU 正在等待 CPU 提供數據批次。
2. **受限於 GPU（運算）**：GPU 已被完全利用以進行數字運算，而 CPU 正在等待它完成。
3. **受限於 I/O 或通信**：時間花費在從磁碟讀取或跨 PCIe/網絡傳輸數據上。

## PyTorch Profiler

PyTorch Profiler API 是了解 PyTorch 模型的執行時間和記憶體消耗的標準工具。它在 C++ 級別和 CUDA 級別跟蹤操作，提供事件的精確時間線。

```python
import torch
import torch.profiler

# 在分析器上下文中包裝您的訓練步驟
with torch.profiler.profile(
    activities=[
        torch.profiler.ProfilerActivity.CPU,
        torch.profiler.ProfilerActivity.CUDA,
    ],
    schedule=torch.profiler.schedule(wait=1, warmup=1, active=3, repeat=1),
    on_trace_ready=torch.profiler.tensorboard_trace_handler('./log/profiler'),
    record_shapes=True,
    profile_memory=True,
    with_stack=True
) as prof:
    for step, (inputs, targets) in enumerate(dataloader):
        if step >= 5:
            break
            
        # 標準訓練步驟
        optimizer.zero_grad()
        loss = model(inputs)
        loss.backward()
        optimizer.step()
        
        # 告訴分析器我們完成了一個步驟
        prof.step()
```

:::tip[性能分析開銷]
性能分析會顯著減慢您的訓練循環。只運行幾個步驟（例如 5-10 個批次）的分析器，而不是一個完整的 epoch。
:::

## 分析輸出

分析數據可以導出為可以使用 PyTorch Profiler 插件在 TensorBoard 中查看的格式。

### 要檢查的關鍵指標

1. **GPU 利用率**：如果您的 GPU 利用率很低（例如 < 80%），您可能遇到了 CPU 數據加載瓶頸。您應該重新檢查您的 `num_workers`、`pin_memory` 和數據增強流水線。
2. **內核時間 (Kernel Time)**：如果 GPU 利用率很高，請查看哪些操作（內核）花費的時間最多。例如，如果卷積很慢，您可能會從 AMP（混合精度）或 TF32 中受益。
3. **記憶體時間線**：分析器可以繪製隨時間變化的記憶體分配情況。記憶體的峰值通常與存儲激活的正向傳播相關。如果峰值太接近您的 VRAM 限制，請考慮梯度檢查點。

## 識別數據加載瓶頸

一種快速且無需代碼即可檢查您是否受限於數據加載的方法是使用 `nvidia-smi` 或 `nvtop` 監控您的 GPU 使用情況。

如果 GPU 利用率持續降至 0%，然後又飆升回 100%，則說明 GPU 在等待下一個批次時處於停滯狀態。在健康的訓練運行期間，利用率應始終保持在較高水平（95%+）。
