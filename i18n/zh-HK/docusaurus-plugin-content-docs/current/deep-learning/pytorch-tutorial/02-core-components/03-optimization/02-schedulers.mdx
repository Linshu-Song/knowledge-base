# 學習率排程

選擇合適的最佳化器固然重要，但在訓練過程中動態調整學習率（Learning Rate, LR）通常是模型能否收斂到全域最優解的關鍵。`torch.optim.lr_scheduler` 模組提供了多種策略，根據當前的訓練輪次（Epoch）或特定的性能指標來自動更新學習率。

## 工作原理

排程器通過封裝一個現有的最佳化器（Optimizer）來工作。它會隨著時間的推移，動態修改最佳化器內部 `param_groups` 中的 `lr` 屬性。

```python
import torch.optim as optim

# 1. 初始化最佳化器
optimizer = optim.AdamW(model.parameters(), lr=0.1)

# 2. 初始化排程器：例如每隔 30 個 Epoch 將學習率縮小為原來的 0.1
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 訓練迴圈
for epoch in range(100):
    train(...)  # 模型訓練
    val(...)    # 模型驗證
    
    # 3. 關鍵：在每個 Epoch 結束時更新學習率
    scheduler.step()
```

:::warning[注意事項]
在 PyTorch 1.1.0 之後的版本中，**`scheduler.step()` 必須在 `optimizer.step()` 之後調用**。如果在其之前調用，會導致訓練的第一個 Epoch 跳過初始學習率，直接從第二次調整後的學習率開始。
:::

## 核心排程策略

PyTorch 內建了豐富的排程機制，適應不同的訓練場景。

### 等間隔衰減：`StepLR` & `MultiStepLR`

這是最基礎的策略。`StepLR` 按固定的週期（`step_size`）進行縮放；而 `MultiStepLR` 則允許你在指定的「里程碑」（`milestones`）處進行縮放。

```python
# 每 30 個 Epoch，LR = LR * 0.1
scheduler = optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 在第 30、80 和 120 個 Epoch 處分別進行衰減
scheduler = optim.lr_scheduler.MultiStepLR(optimizer, milestones=[30, 80, 120], gamma=0.1)
```

### 性能觸發衰減：`ReduceLROnPlateau`

當監測的指標（如驗證集損失）停止改善時，該排程器會自動降低學習率。這非常有助於模型跳出「鞍點」或在平台期進一步細化權重。

```python
scheduler = optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode='min', factor=0.1, patience=10)

# 迴圈內部：需要手動傳入當前的監控指標
for epoch in range(100):
    val_loss = val(...)
    scheduler.step(val_loss) # 排程器根據 val_loss 的表現決定是否調整
```

### 餘弦退火：`CosineAnnealingLR`

按照餘弦波形的軌跡動態調整學習率。這種方法非常流行，因為它在前期保持較高的學習率以快速搜尋，中後期平滑下降，最後以極小的步長收斂，通常能獲得更好的泛化性能。

```python
# T_max 通常設定為總訓練步數或總 Epoch 數
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=100, eta_min=1e-6)
```

### 單週期策略：`OneCycleLR`

單週期策略（One Cycle Policy）是近年來極受推崇的技术。它將學習率從一個較低的值逐漸攀升到一個極高峰值（暖機階段），然後再平滑下降到一個遠低於初值的水平。這種「大幅度震盪」有助於跳過局部最優，常能實現所謂的「超收斂（Super-convergence）」。

```python
# 需要知道每輪的步數（DataLoader 的長度）
scheduler = optim.lr_scheduler.OneCycleLR(
    optimizer, 
    max_lr=1e-2, 
    steps_per_epoch=len(train_loader), 
    epochs=100
)

# 注意：OneCycleLR 通常是按「步 (Batch)」更新，而不是按「輪 (Epoch)」
for epoch in range(100):
    for batch in train_loader:
        train(...)
        scheduler.step() # 每個 Batch 更新一次
```

## 排程器對比與選型

| 排程器 | 最佳應用場景 | 優缺點對比 |
| :--- | :--- | :--- |
| **StepLR / MultiStepLR** | 傳統經典架構 (如 ResNet) | 邏輯清晰直觀 / 硬性階梯式下降可能導致訓練曲線抖動。 |
| **ReduceLROnPlateau** | 不確定具體需要多少 Epoch 才能收斂時 | 動態自適應，隨壞隨調 / 容易受到評估指標波動的干擾。 |
| **CosineAnnealingLR** | 現代網路訓練的標準配置 | 軌跡平滑，收斂穩健 / 需提前明確訓練總時長 (`T_max`)。 |
| **OneCycleLR** | 追求極速收斂，針對複雜任務 (NLP/CV) | 能極大縮短訓練時間 / 對 `max_lr` 的選取較為敏感。 |
