模型编译

从历史上看，PyTorch 完全在动态图模式 (Eager Mode) 下运行。这意味着每个操作（例如，矩阵乘法、ReLU、加法）都独立执行，一个接一个地执行。虽然动态图模式非常适合调试和动态图，但它牺牲了大量性能，因为框架无法看到“全局”来优化操作。

在 PyTorch 2.0 中引入的 torch.compile 将图编译带到了 PyTorch，同时保持了动态图模式的体验。

torch.compile 是如何工作的​

通过编译模型，PyTorch 在运行操作之前分析操作序列。它使用一个名为 TorchInductor 的后端将操作融合在一起。

例如，如果您的模型执行加法然后执行 ReLU，动态图模式需要：

  1. 从 VRAM 读取张量 A。
  2. 从 VRAM 读取张量 B。
  3. 将它们相加，将结果写回 VRAM。
  4. 从 VRAM 读取结果。
  5. 应用 ReLU，将最终结果写入 VRAM。

编译后的模型将融合这些操作成为单个自定义内核，从而大幅降低所需的内存带宽（这通常是现代 GPU 的主要瓶颈）。

编译模式​

torch.compile 接受一个 mode 参数来控制其优化的积极程度：

  • default：平衡编译时间和性能。非常适合大多数用例。
  • reduce-overhead：大幅优化执行以减少 Python 开销。非常适合小型模型，在这些模型中，Python 开销占执行时间的很大一部分。使用 CUDA 图 (CUDA graphs)。
  • max-autotune：分析多个不同的 CUDA 内核并选择最快的一个。编译需要很长时间，但可以产生最快的执行速度。将其用于最终的生产训练运行或推理。

在 PyTorch 中，编译只是包装实例化模型的一个函数调用：

import torch
import torchvision.models as models

model = models.resnet50()

# 编译模型
fast_model = torch.compile(model, mode="default")

# 正常使用编译后的模型进行训练或推理
for inputs, targets in dataloader:
    outputs = fast_model(inputs)

图断裂 (Graph Breaks)​

有时，torch.compile 会遇到无法安全编译成图的 Python 代码（例如，打印张量的值、复杂的数据依赖控制流）。发生这种情况时，它会执行图断裂。

模型回退到动态图模式，执行复杂的 Python 代码，然后开始为剩余的操作编译新图。

尽量减少图断裂

虽然 torch.compile 仍然可以在有图断裂的情况下工作，但性能会下降。为了获得最大速度，您需要一个单一的、连续的图。您可以通过查看编译日志来调试图断裂。
