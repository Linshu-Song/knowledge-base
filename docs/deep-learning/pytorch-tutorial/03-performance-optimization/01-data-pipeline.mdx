# Data Pipeline Optimization

When training deep learning models, the GPU is often much faster than the CPU. If the CPU cannot load and preprocess data fast enough, the GPU will sit idle waiting for data. This is known as a **CPU bottleneck** or **I/O bottleneck**. 

Optimizing the data pipeline primarily involves configuring the standard PyTorch `DataLoader` correctly.

## Number of Workers

The `num_workers` argument in `DataLoader` determines how many subprocesses are used for data loading.

:::tip[Optimal num_workers]
A common rule of thumb is to set `num_workers` to the number of CPU cores available, or `4 * num_gpus`. However, setting it too high can cause excessive overhead and memory consumption. Always benchmark to find the sweet spot.
:::

## Pinned Memory

When training on a GPU, data must be transferred from CPU RAM to GPU VRAM. By default, this transfer is pageable, meaning the OS can move it around. Pinning memory locks the data in a specific RAM location, allowing for much faster, asynchronous data transfers to the GPU.

:::note[When to use pin_memory]
Always set `pin_memory=True` when training on GPUs. If you are training strictly on CPU, leave it as `False`.
:::

## Persistent Workers

By default, PyTorch destroys worker processes at the end of an epoch and recreates them at the start of the next. This teardown and spin-up takes time. 

:::info[Persistent Workers]
Setting `persistent_workers=True` keeps the worker processes alive between epochs. This eliminates the initialization overhead at the start of every epoch, which is especially noticeable for small datasets or fast epochs.
:::

## DataLoader Configuration Example

These optimizations are applied directly when initializing your `DataLoader`:

```python
from torch.utils.data import DataLoader

train_loader = DataLoader(
    dataset=train_dataset,
    batch_size=32,
    num_workers=8,               # 1. Parallel workers
    pin_memory=True,             # 2. Fast CPU-to-GPU transfer
    persistent_workers=True,     # 3. Avoid epoch restart overhead
    prefetch_factor=2            # 4. Buffer batches in advance
)
```
