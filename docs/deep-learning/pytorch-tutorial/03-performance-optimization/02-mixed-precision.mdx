# Mixed Precision Training

By default, PyTorch uses 32-bit floating-point numbers (`float32` or FP32) for all tensor operations. However, modern GPUs contain specialized hardware (like Tensor Cores) optimized for lower precision formats like 16-bit floats (`float16` or FP16) and `bfloat16` (BF16).

**Automatic Mixed Precision (AMP)** intelligently runs some operations in lower precision to save memory and increase speed, while keeping operations that require higher dynamic range in `float32`.

## The Benefits of Lower Precision

1. **Faster Compute**: Tensor Cores can process 16-bit math orders of magnitude faster than 32-bit math.
2. **Reduced Memory**: Gradients, activations, and weights take up less VRAM, allowing for larger batch sizes or larger models.
3. **Memory Bandwidth**: Moving 16-bit data takes half the time of 32-bit data, alleviating memory bandwidth bottlenecks.

## FP16 (Float16)

FP16 represents numbers using 1 sign bit, 5 exponent bits, and 10 fraction bits. Because it has fewer exponent bits than FP32, it has a narrower dynamic range, which can sometimes lead to gradient underflow (gradients becoming zero). AMP uses a **Gradient Scaler** under the hood to prevent this.

```python
import torch

scaler = torch.amp.GradScaler('cuda')

for inputs, targets in dataloader:
    optimizer.zero_grad()
    
    # Cast operations to mixed precision
    with torch.amp.autocast('cuda', dtype=torch.float16):
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        
    # Scale the loss and call backward to create scaled gradients
    scaler.scale(loss).backward()
    
    # Unscale gradients and update weights
    scaler.step(optimizer)
    scaler.update()
```

## BF16 (BFloat16)

BF16 allocates 8 bits to the exponent (same as FP32) and 7 bits to the fraction. This means it has the **exact same dynamic range as FP32**, eliminating gradient underflow issues. However, it sacrifices fractional precision.

BF16 is heavily preferred for training Large Language Models (LLMs) and other unstable architectures because it does not require a Gradient Scaler.

:::warning[Hardware Requirements]
BF16 requires Ampere architecture GPUs (e.g., RTX 30-series, A100) or newer. If you are using older GPUs (like V100 or RTX 20-series), you must stick with standard FP16.
:::

```python
import torch

for inputs, targets in dataloader:
    optimizer.zero_grad()
    
    # BF16 does not require a GradScaler
    with torch.amp.autocast('cuda', dtype=torch.bfloat16):
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        
    loss.backward()
    optimizer.step()
```

## TensorFloat-32 (TF32)

TF32 is a special format introduced in Ampere GPUs. It uses 8 bits for the exponent (like BF16/FP32) and 10 bits for the fraction (like FP16). 

Unlike FP16/BF16, TF32 is **not** a data type you cast your tensors to. Instead, it is an internal execution mode for Tensor Cores. When you multiply two FP32 matrices, the GPU can internally execute the math using TF32, providing a massive speedup with almost zero code changes.

:::info[Enabling TF32]
PyTorch disables TF32 for matrix multiplications by default to ensure perfect reproducibility. To enable it for a free speed boost on Ampere+ GPUs, run this globally at the start of your script.
:::

```python
import torch

# Must be run globally before initialization
torch.set_float32_matmul_precision('high')
```
