# Model Compilation

Historically, PyTorch operated entirely in **Eager Mode**. This means every operation (e.g., matrix multiplication, ReLU, addition) is executed independently, one by one. While eager mode is fantastic for debugging and dynamic graphs, it leaves a lot of performance on the table because the framework cannot see the "bigger picture" to optimize operations.

Introduced in PyTorch 2.0, `torch.compile` brings graph compilation to PyTorch while maintaining the feel of eager mode.

## How `torch.compile` Works

By compiling the model, PyTorch analyzes the sequence of operations before running them. It uses a backend called **TorchInductor** to fuse operations together.

For example, if your model performs an Addition followed by a ReLU, eager mode requires:
1. Reading tensor A from VRAM.
2. Reading tensor B from VRAM.
3. Adding them, writing the result back to VRAM.
4. Reading the result from VRAM.
5. Applying ReLU, writing the final result to VRAM.

A compiled model will **fuse** these into a single custom kernel, drastically reducing the memory bandwidth required (which is often the main bottleneck in modern GPUs).

## Compilation Modes

`torch.compile` accepts a `mode` argument to control how aggressively it optimizes:

*   **`default`**: Balances compilation time and performance. Excellent for most use cases.
*   **`reduce-overhead`**: Heavily optimizes the execution to reduce Python overhead. Ideal for small models where Python overhead is a significant portion of execution time. Uses CUDA graphs.
*   **`max-autotune`**: Profiles multiple different CUDA kernels and picks the fastest one. Compiling takes a long time, but yields the fastest possible execution. Use this for final production training runs or inference.

In PyTorch, compilation is simply a function call wrapping your instantiated model:

```python
import torch
import torchvision.models as models

model = models.resnet50()

# Compile the model
fast_model = torch.compile(model, mode="default")

# Train or infer with the compiled model normally
for inputs, targets in dataloader:
    outputs = fast_model(inputs)
```

## Graph Breaks

Sometimes, `torch.compile` encounters Python code it cannot safely compile into a graph (e.g., printing a tensor's value, complex data-dependent control flow). When this happens, it performs a **Graph Break**. 

The model falls back to eager mode, executes the tricky Python code, and then starts compiling a new graph for the remaining operations.

:::warning[Minimize Graph Breaks]
While `torch.compile` will still work with graph breaks, performance will degrade. For maximum speed, you want a single, continuous graph. You can debug graph breaks by reviewing the compilation logs.
:::
