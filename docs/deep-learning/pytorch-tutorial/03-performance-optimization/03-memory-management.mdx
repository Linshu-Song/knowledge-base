# Memory Optimization

Training large models often hits the physical limits of GPU VRAM. When you encounter an Out Of Memory (OOM) error, you cannot simply buy a larger GPU immediately. Instead, you can utilize several memory optimization techniques to trade compute time for VRAM space.

## Gradient Accumulation

When you reduce your batch size to avoid OOM errors, the gradients become noisier, which can harm convergence. **Gradient Accumulation** allows you to simulate a large batch size by accumulating gradients over multiple smaller forward/backward passes before actually updating the weights.

For example, a batch size of 64 can be simulated by running 4 batches of 16, accumulating the gradients, and then performing the optimizer step. This keeps the memory usage tied to a batch size of 16 while providing the stability of a batch size of 64.

In native PyTorch, this requires carefully placing the `zero_grad()` and `step()` calls:

```python
# Number of mini-batches to accumulate before stepping
accumulation_steps = 4

optimizer.zero_grad()

for i, (inputs, targets) in enumerate(dataloader):
    outputs = model(inputs)
    
    # Scale the loss to account for the accumulation
    loss = criterion(outputs, targets) / accumulation_steps
    loss.backward()  # Gradients accumulate here
    
    # Perform optimization step only every `accumulation_steps` iterations
    if (i + 1) % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()  # Reset gradients for the next accumulation cycle
```

## Gradient Checkpointing

During the forward pass, PyTorch saves intermediate activations in memory because they are needed to compute gradients during the backward pass (backpropagation). For very deep models, storing these activations consumes the vast majority of VRAM.

**Gradient Checkpointing** (or Activation Checkpointing) discards these intermediate activations to save memory. During the backward pass, PyTorch recomputes them on the fly. This significantly reduces VRAM usage at the cost of about 20-30% longer training time.

:::info[Trading Compute for Memory]
Checkpointing is the ultimate "compute-for-memory" tradeoff. It is essential when training foundation models or processing ultra-high-resolution images.
:::

To implement this, you wrap your sub-modules in `torch.utils.checkpoint.checkpoint` during the `forward` pass.

```python
import torch.nn as nn
from torch.utils.checkpoint import checkpoint

class DeepModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer1 = nn.Sequential(...)
        self.layer2 = nn.Sequential(...)

    def forward(self, x):
        # Normal forward pass uses high memory
        # x = self.layer1(x)
        
        # Checkpointed forward pass saves memory, recalculates in backward
        x = checkpoint(self.layer1, x, use_reentrant=False)
        x = checkpoint(self.layer2, x, use_reentrant=False)
        return x
```

## Gradient Clipping

While primarily a technique to prevent exploding gradients (numerical instability), gradient clipping can also prevent `NaN` values from propagating and corrupting your optimizer state. This is especially useful when using mixed precision formats where the dynamic range is limited.

```python
import torch

loss.backward()

# Clip the norm of the gradients to 1.0 before taking a step
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

optimizer.step()
```
