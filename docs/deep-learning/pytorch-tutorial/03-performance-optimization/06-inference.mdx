# Inference Optimization

Training focuses on throughput (samples processed per second) and memory efficiency (gradients). Inference prioritizes **latency** (time taken for a single prediction) and **throughput**.

Because we do not need to compute gradients or update weights during inference, we can apply several optimizations that are invalid during training.

## The Inference Context

When running a PyTorch model for inference, there are two mandatory steps:

1. **Evaluation Mode**: Switches layers like Dropout and BatchNorm to evaluation mode. Dropout is disabled, and BatchNorm uses its learned running statistics instead of the batch statistics.
2. **Disable Gradients**: Disabling gradient tracking prevents PyTorch from storing intermediate activations, massively saving memory and compute time.

```python
import torch

# Disables Dropout, triggers evaluation paths for BatchNorm
model.eval()

# Bypasses gradient tracking and intermediate activation storage completely
with torch.inference_mode():
    predictions = model(input_batch)
```

## Graph Optimizations (`torch.compile`)

While `torch.compile` accelerates training, it shines brightest in inference. By fusing operations (e.g., convolution + ReLU), memory bandwidth usage drops significantly.

For production inference, `max-autotune` mode is typically used to discover the fastest possible kernels for your specific GPU architecture.

```python
import torch

# Fuses operators into unified execution kernels
fast_model = torch.compile(model, mode="max-autotune")

with torch.inference_mode():
    output = fast_model(input_batch)
```

## Exporting for Production

Running raw PyTorch models in production (e.g., inside a Python server like FastAPI or Flask) is often suboptimal due to Python's Global Interpreter Lock (GIL) and overhead. Instead, models are typically exported to faster runtimes.

### ONNX

The **Open Neural Network Exchange (ONNX)** is a widely supported format. You can export a PyTorch model to ONNX, which can then be run using ONNX Runtime (C++) or TensorRT (NVIDIA).

### TensorRT

NVIDIA's **TensorRT** is the gold standard for deploying models on NVIDIA GPUs. It performs aggressive layer fusion, precision calibration (e.g., INT8 quantization), and kernel auto-tuning for your specific GPU model. PyTorch models can be converted to TensorRT via ONNX, or directly using `Torch-TensorRT`.

For detailed guides on converting and deploying with ONNX or TensorRT, please refer to the Fundamental Deep Learning sections.
:::

## Quantization

While Mixed Precision (FP16/BF16) is common in training, inference can often tolerate **INT8** precision. 

Quantization maps the continuous space of floating-point weights into 8-bit integers. This reduces the model size by 4x and memory bandwidth by 4x, providing immense speedups on modern GPUs equipped with Integer Tensor Cores.

*   **PTQ (Post-Training Quantization)**: The easiest method. The trained FP32 model is converted to INT8 using a small calibration dataset to find the min/max bounds of the activations.
*   **QAT (Quantization-Aware Training)**: If PTQ severely harms the model's accuracy, QAT simulates the quantization error during training, allowing the model to adapt and retain accuracy.
